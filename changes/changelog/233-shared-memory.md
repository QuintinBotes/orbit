section: Off by default
- **Shared memory store (#233).** Set `knowledge.shared_memory: { enabled: true, command: [memory] }` to share lessons with the memory plugin. With `lessons_in_prompts: true` too, a worker's advisory block also carries items from it, with their ids, inside the same fence, `max_advisory_tokens` and `max_prompt_lessons` (shared items take only the room the local lessons leave); proposals and feedback do not need `lessons_in_prompts`. when a run ends, each lesson it left validated is proposed to memory with the run as evidence, and a recalled item whose failure the run repeated is reported wrong through memory's feedback call. Orbit never activates an item. The memory command runs with a minimal environment (no provider keys) and is killed on a timeout. If it is unreachable the run goes on without it for the rest of that run and records `learning.memory-unavailable` once; `orbit doctor` checks the command. Orbit's own lesson store works the same either way, and without the key nothing changes.
