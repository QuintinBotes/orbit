section: Fixes
- **A candidate denied for out-of-scope paths no longer comes back the same way (#280).** A build that rewrote files outside `scope.allowed_paths` stayed in the implementer's worktree, so each repair was denied again until the run ended over a size limit. Before the next attempt, Orbit now restores those paths to the base revision in that worktree (a file the base does not have is removed), keeps the in-scope edits and names the paths in the repair brief. The run blocks, naming them, when a repair produces the denied tree again, or when a criterion needs one of them. What scope inspection allows or denies is unchanged, and a protected-path denial still blocks as a policy violation.
