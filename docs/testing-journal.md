A running record of what we tested, what worked, what went wrong, why, and
what changed as a result. Newest entries at the top. Each entry ends with a
status: **fixed** (with the commit), **open** (with the gap id from
`docs/gaps.md`), or **watch** (no change yet, keep an eye on it).

### 2026-10-07: workers and loopback: Seatbelt cannot limit a listener (#31, maintainer decision)
- Tested: on macOS 27.0.1 with `srt` 0.0.78 and Claude Code 2.1.292, a Node listener in the sandbox on 127.0.0.1, ::1, ::ffff:127.0.0.1, 0.0.0.0 and `::`, and a connection from outside made to the machine's LAN address for the wildcards: `srt` with `allowLocalBinding` admitted all and each wildcard answered on the LAN address; without it all were refused (EPERM); the real `claude -p` with the settings Orbit wrote for an implementer (`allowLocalBinding: true`) did the same, and `false` refused all. Then the maintainer's fix, a loopback-only rule set in the `srt` preload with `srt`'s rule off, each candidate inserted by the preload under the real `srt`: `(local ip "localhost:*")` on bind and inbound admitted 0.0.0.0, `::` and the LAN address itself, each answering on the LAN address; `network-inbound` alone gates `listen()`; `tcp4` the same, `ip6` divides by family; a numeric host is refused by `sandbox-exec`; a `remote` filter on inbound refuses every listener, and a deny by peer does not stop an accepted connection. Reproduced with bare `sandbox-exec`. From `srt`'s source: on Linux every sandbox gets `bwrap --unshare-net` and `allowLocalBinding` is not passed. Tests written first and failing first for the final behaviour, then under the real `srt` and the real CLI: the ten runner shapes (listening ones refused in a worker on macOS, passing with `srt`'s binding), the bind matrix for the worker and a check profile, the Seatbelt pin, and the claude-sandbox session with the issue's `dotnet test -m:1`.
- Went well: the measurement settled the question before any rule shipped: the requested proof (binding 0.0.0.0 refused) could not pass, so no rule set claiming loopback only was added.
- Went wrong: two first measurement runs measured nothing (zsh did not split the address pair, and macOS has no `timeout`); caught because every case failed the same way under both settings, and rerun. The branch's first form had let workers use `srt`'s and Claude Code's broad rule.
- Root cause: Seatbelt checks a listener once, at `listen()`, against its local address, and its address filter takes only `*` or `localhost`, which matches every address of the machine; there is no loopback-only listener in either worker tier on macOS.
- Change: on this branch. Workers get no permission to listen in either tier (`profileForWorker`, the adapter, the settings and their schema `const`); `network.local_binding` is removed (never released); checks unchanged; doctor's `workers.loopback` warns on macOS for .NET and Gradle repositories; ADR 0001 "Workers and loopback" holds the measurements. Supersedes the two entries below, whose key and ADR heading are gone. Open: a policy switch to opt workers into the broad rule knowingly (maintainer's call); checks' listeners reach the network on macOS (existing). Not measured: Linux, real Gradle and Maven, a connection from another machine (a connection made to the machine's own LAN address stands in).
